# KAMP 프로젝트

KAMP 대회 준비를 위한 팀 저장소입니다. 팀원은 **NBJ, YSJ, YSH**이며, 질문과 가설을 중심으로 실험하고 검증한 결과를 공유합니다.

대회 데이터와 세부 과제는 아직 공개되지 않았습니다. 과제, 데이터 구조, 평가 지표, 검증 방식, 모델링 방법은 모두 **TODO**입니다.

## 폴더 안내

| 경로 | 역할 |
|---|---|
| `.github/` | 실험·버그 Issue 및 Pull Request 템플릿 |
| `docs/` | 대회 개요, 데이터 사전, 검증 전략, 실험 규칙, 의사결정 기록 |
| `data/` | 로컬 데이터 보관 안내. 원본 데이터와 생성 데이터는 Git 제외 |
| `experiments/{NBJ,YSJ,YSH}/` | 개인별 실험 공간과 누적 실험기록 |
| `src/` | 실험에서 검증되어 팀 전체가 재사용하는 공용 코드 |
| `templates/` | 실험계획·실험결과 양식 및 실험기록 작성 예시 |
| `outputs/` | 그림·표 등 로컬 산출물 안내. 대용량 산출물은 Git 제외 |

`experiments/`에는 개인이 질문과 가설을 검증하는 코드를 둡니다. `src/`에는 검증 후 재사용 가치와 영향 범위를 확인한 공용 코드만 승격합니다. 개인의 일회성 코드를 바로 공용 코드로 넣지 않습니다.

## 실험 흐름

1. 작업 브랜치에서 담당자의 `experiments/<이니셜>/` 아래에 `EXP001_짧은이름`, `EXP002_짧은이름` 순으로 폴더를 만듭니다. 번호는 개인별로 관리하며, 공유할 때는 `NBJ/EXP001_짧은이름`처럼 표기합니다.
2. `templates/실험계획_template.md`를 복사해 `실험계획.md`를 작성합니다. 가능하면 하나의 질문과 가설만 검증합니다.
3. 계획에 따라 실행하고 재현에 필요한 설정, 명령, 데이터 버전 및 결과 위치를 기록합니다.
4. 종료 후 `실험결과.md`를 작성하고 개인 `실험기록.md`에 표 한 행과 3~4줄 요약을 남깁니다. 실패도 기록합니다.
5. 검증된 공용 코드는 리뷰를 거쳐 `src/`로 승격하고, 팀 결정은 `docs/decisions.md`에 기록합니다.

EDA / PREPROCESSING / FEATURE / ML / DL / VALIDATION / ERROR_ANALYSIS 등은 **폴더가 아니라 실험계획과 실험기록의 metadata**로 관리합니다. 현재 실제 실험은 시작하지 않았으므로 EXP 폴더는 없습니다.

## 작업 원칙과 준비 상태

- `main`에 직접 작업하거나 push하지 않고 작업 브랜치와 PR을 사용합니다.
- 원본 데이터, 비밀값, 대용량 파일을 commit하지 않습니다. `.gitignore`만 믿지 말고 staged diff를 확인합니다.
- 실행 환경 및 라이브러리: TODO. `requirements.txt`에는 아직 패키지를 지정하지 않았습니다.
- 대회명·공식 자료·목표·일정: TODO → `docs/project_overview.md`
- 데이터 수령·구조·사용 조건: TODO → `data/README.md`, `docs/data_dictionary.md`
- 평가 지표·검증 설계·Baseline: TODO → `docs/validation_strategy.md`

대회 자료 공개 후에는 프로젝트 개요 → 데이터 안내·사전 → 검증 전략 → 의존성 → 첫 실험계획 순으로 채웁니다. 세부 규칙은 [실험 규칙](docs/experiment_rules.md)과 각 `AGENTS.md`를 따릅니다.
