# NBJ-006 실험설계 요약 — 센서 파생변수가 비지도 모델에 도움이 되는가?

**상태: 실행 전.** [상세 계획](실험계획.md)과 [분석 Notebook](NBJ-006_final_unsupervised.ipynb)을 검토하기 위한 문서다. 아래에는 NBJ-006 결과가 없다.

**실행 방식 변경:** Jupyter 미설치 및 uv interpreter의 `EXTERNALLY-MANAGED` 상태 때문에 환경을 변경하지 않고 [일반 Python runner](run_nbj006.py)에서 동일한 18개 코드 셀을 순서대로 실행한다. `display`를 화면의 텍스트 출력 함수로 바꾸는 것 외에 분석 설계·조건·모델·평가 기준은 동일하다. 모델 결과를 보기 전에 정한 실행환경 호환 변경이며, 원본 Notebook은 실행 전 골격으로 보존한다. 현재 runner는 생성·정적 검증만 마쳤고 실행하지 않았다.

## 출발점과 이유

NBJ-005는 용접기 원본 센서 **Force·Current·Voltage·Weld Time** 네 값으로 K-Means와 Isolation Forest(IF)를 저장·재로드·추론할 수 있게 만들었다. 기존 실행에서 train 8,470행과 follow-up 3,469행, 고정 K=2·seed=42·IF 문턱을 사용했고, 저장 결과 재현 검증을 통과했다. 그러나 그 군집이 확정된 물리적 운전 상태인지, IF 후보가 실제 불량품인지는 알 수 없다.

NBJ-006에서는 **알고리즘을 추가하지 않고** 입력 표현만 바꾼다. 네 원값으로 만든 간단한 proxy가 군집과 이상도 순위에 어떤 변화를 주는지, 그리고 그 변화가 여러 무작위 seed에서 안정적인지 확인한다.

## 세 가지 proxy와 다섯 가지 비교

| 이름 | 식 | 읽는 법과 주의점 |
|---|---|---|
| `R_proxy` | Voltage ÷ Current | 겉보기 저항을 흉내 낸 값. 전류가 kA여서 수치 단위는 V/kA. 실제 접촉저항이나 동저항을 직접 잰 값은 아니다. |
| `VI_t_proxy` | Voltage × Current × Weld Time | 전기적 에너지 입력의 대리값. 전압·전류 파형을 시간에 따라 적분하지 않았으므로 실제 용접 입열량이 아니다. |
| `I2_t_proxy` | Current² × Weld Time | 전류·통전시간 가열 일정의 대리값. 실제 Joule 발열량 `I²Rt`에서 저항 R이 없으므로 열량이라고 부르지 않는다. |

비교 대상은 `FS0_RAW4`(원본 네 값), `FS1_R`(+저항 proxy), `FS2_ENERGY`(+전기 입력 proxy), `FS3_I2T`(+전류·시간 proxy), `FS4_ALL`(세 proxy 모두)이다. 원본 네 값은 모든 set에 남긴다. 새 변수를 하나씩 더한 set과 모두 더한 set을 함께 보면 **어느 표현에서 차이가 생기는지** 확인할 수 있다. 세 proxy는 기존 센서에서 계산했으므로 새로운 독립 측정정보는 아니다. 비교 전 train의 상관·분포·Weld Time 고유값을 확인하되, 상관이 높다는 이유만으로 임의 삭제하지 않는다.

## 같은 조건에서 무엇을 비교하는가?

모든 set은 NBJ-005와 동일한 날짜 분할, train에만 맞춘 모델별 StandardScaler, K=2 K-Means와 같은 설정의 IF를 쓴다. seed는 결과를 보고 고르는 대신 **`[0, 1, 2, 3, 42]`로 미리 고정**한다. seed가 바뀌어도 비슷한 행들이 군집에 묶이고, 이상도 순위와 후보 집합이 비슷하면 구조가 더 안정적이라고 본다. 군집 번호 0·1은 뒤바뀔 수 있어 번호가 아닌 **ARI**로 비교한다. IF는 연속 점수 순위의 **Spearman 상관**과 후보 집합의 **Jaccard 겹침**을 함께 본다.

첫 관문은 `FS0_RAW4, seed=42`가 NBJ-005 저장 결과를 재현하는지 확인하는 것이다. 전체 11,939행의 군집·IF 후보 등 이산 결과는 정확 일치, 거리·점수·문턱은 기존 허용오차 `rtol=1e-10`, `atol=1e-12`로 확인한다. 실패하면 후속 set 비교를 멈춘다. 새 set의 IF 문턱은 NBJ-005 숫자를 복사하지 않고 **각 set·seed의 train 점수 95% 분위수**로 정한다. 후보는 문턱 이상인 행일 뿐 실제 불량품이 아니다.

군집 번호는 set마다 뒤바뀔 수 있어 날짜별 군집 1 비율을 비교할 때에는 seed 42의 두 군집을 FS0 군집과 **같은 행이 최대한 많이 겹치도록** 0/1 대응시킨다. 대응표와 겹친 행 수를 남긴다. 번호 교환의 영향을 받지 않는 ARI 계산은 그대로 유지한다. Train 후보 비율은 자기 train 점수의 95% 경계로 정하면 구조상 대략 5%다. 비교표에 남겨 **문턱 적용 확인**에만 쓰며 어느 모델이 더 낫다는 근거로 쓰지 않는다.

## 최종 후보를 고르는 방식과 알 수 없는 것

Notebook은 각 set의 군집 분리도, seed 간 안정성, FS0 대비 변화, 후보 비율·변경 행의 센서 조건, proxy 중복성·해석 한계를 **하나의 비교표**로 제시한다. 한 지표의 최고값으로 자동 우승 모델을 정하지 않고 사람이 안정성·재현성·설명 가능성·간결성을 함께 검토한다. proxy의 추가 가치가 불분명하면 **Raw4를 유지하는 것도 정상적인 결론**이다.

날짜별 기재 불량 건수와 함께 움직이는지는 참고로만 본다. 원본 Excel `result` 시트에는 불량 건수·유형만 있고 **검사 수량이나 생산 수량 분모가 없다**. NBJ-004 CSV는 날짜별 Raw 행 수로 나눈 `1,000기록당 기재 불량 건수`를 사용했고, 그 행 수가 원본 Raw의 9일 행 수와 일치함을 확인했다. 이는 실제 불량률이 아니라 보조 지표다. 3/27 기록은 없고 3/31은 유형 기록이 일부 빠져 있다. 어느 센서 행이 어느 불량 제품인지 연결하는 label도 없다. 따라서 이 실험으로 불량 예측 정확도·선행시간·인과관계는 알 수 없다. 군집이나 이상 후보를 정상/불량이라고 부르지 않는다.

실행 전에는 NBJ-005에 기록된 **실제 Python 실행 파일 경로와 `PYTHONPATH`**가 현재 환경과 정확히 같은지 확인하며, 다르면 모델 fit 전에 멈춘다.
