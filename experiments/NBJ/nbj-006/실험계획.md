## 연구 질문·가설

**Primary question:** NBJ-005의 Raw 4변수 K-Means/Isolation Forest와 비교해 해석 가능한 파생변수를 추가하면 더 안정적이고 해석 가능한 공정 상태·이상도 표현을 얻는가?

- **H1:** 물리 proxy를 추가하면 Raw4와 다른 anomaly 순위·후보 집합이 나타날 수 있다. 변화 자체는 개선의 증거가 아니다.
- **H2:** 최종 후보로 유용하려면 특정 seed 하나에만 의존하지 않고 여러 seed에서 군집·이상도 구조가 안정적으로 재현되어야 한다.

가설 판정에 임의의 성공률 cutoff를 추가하지 않는다. 날짜별 불량 기록과의 관계는 탐색적으로만 본다.

## 데이터 분할과 feature 정의

NBJ-005와 같이 날짜 `<= 2020-03-31`을 **train 8,470행**, 그 뒤를 **follow-up 3,469행**으로 두며 전체는 **11,939행**이다. 원본 행 순서와 Excel 행 번호를 보존한다. 학습, StandardScaler fit, train score 문턱 산출에 follow-up을 사용하지 않는다.

고정 Raw 순서는 `weld force(bar)`, `weld current(kA)`, `weld Voltage(v)`, `weld time(ms)`다. 파생변수는 원단위 값에서 각 행별로 만든 뒤 scaler에 넣는다.

| Set | 순서대로 사용할 입력 |
|---|---|
| `FS0_RAW4` | Raw 4 |
| `FS1_R` | Raw 4, `R_proxy = Voltage / Current` |
| `FS2_ENERGY` | Raw 4, `VI_t_proxy = Voltage × Current × Weld Time` |
| `FS3_I2T` | Raw 4, `I2_t_proxy = Current² × Weld Time` |
| `FS4_ALL` | Raw 4, `R_proxy`, `VI_t_proxy`, `I2_t_proxy` |

`R_proxy`는 겉보기 저항 proxy이고 수치 단위는 V/kA다. 실제 접촉저항·동저항 측정치라고 단정하지 않는다. `VI_t_proxy`는 전기적 에너지 입력 proxy로 수치 단위 V·kA·ms이며 파형 적분으로 구한 실제 입열량이 아니다. `I2_t_proxy`는 전류·시간 기반 가열 일정 proxy로 수치 단위 kA²·ms이며 `I²Rt`에서 R이 빠져 실제 Joule 발열량이 아니다. 셋 모두 원래 네 센서에서 계산됐으므로 새 독립 센서정보라고 표현하지 않는다. Current 0 또는 비유한값이 발견되면 임의 보간 없이 중단하고 기록한다.

모델 비교 전에 **train**에서 Raw와 파생변수 7개의 기술통계, Pearson·Spearman 상관, heatmap, 파생변수끼리의 상관, Weld Time의 고유값·빈도를 확인한다. 상관이 높아도 이번 비교에서 feature를 삭제하지 않는다.

## 모델과 고정 설정

모든 feature set에서 K-Means용 `StandardScaler()`와 IF용 `StandardScaler()`를 **각각 train에만 fit**한다. 두 모델 모두 같은 set의 고정 순서 feature를 사용한다. follow-up에는 저장된 scaler의 `transform`만 적용한다. 원본 중복행·극단값을 임의 제거하지 않는다.

| 모델 | NBJ-005에서 확인한 고정값 |
|---|---|
| K-Means | `K=2`, `init='k-means++'`, `n_init=20`, `max_iter=300`, `tol=1e-4`, `algorithm='lloyd'`; NBJ-005 기본값 `copy_x=True`, `verbose=0` |
| Isolation Forest | `n_estimators=300`, `max_samples=256`, `max_features=1.0`, `bootstrap=False`, `contamination='auto'`, `n_jobs=4`; NBJ-005 기본값 `verbose=0`, `warm_start=False` |
| Seed | `SEEDS = [0, 1, 2, 3, 42]`; seed 42만 NBJ-005 재현 anchor이며 결과를 보고 seed를 고르지 않음 |
| IF score | `-score_samples` (클수록 희소) |
| IF 문턱 | **FS0 seed 42:** NBJ-005 고정값 `0.6079581703468012`로 기존 candidate를 정확 재현. **FS0의 다른 seed와 FS1~4 모든 seed:** 해당 set·seed의 train score `np.quantile(scores, .95, method='linear')`; candidate는 `score >= threshold`. NBJ-005 문턱 숫자를 새 set에 복사하지 않음 |

K와 contamination, feature 집합, seed, scaler, 문턱 규칙은 결과를 본 뒤 바꾸지 않는다. IF의 sklearn 기본 `predict` 판정을 candidate로 사용하지 않는다.

## 비교 지표·판단 방법

K-Means는 각 set·seed의 **train 전체 silhouette**, train/follow-up cluster 크기, 날짜별 share, seed 쌍의 전체 11,939행 Adjusted Rand Index(ARI)를 기록한다. seed 42 군집은 NBJ-005의 전체 행과 ARI로 비교한다. 군집 ID는 서로 치환될 수 있으므로 새 set 간 ID 직접 일치율로 판단하지 않는다. seed 42에서 군집별 Raw 및 포함된 파생변수의 median/IQR을 설명한다.

날짜별 품질 탐색에 쓰는 `aligned_cluster1_share`는 각 set의 seed 42 군집 번호를 FS0 seed 42에 맞춰 **전체 11,939행 overlap 합계가 최대**인 0/1 대응으로 정렬한 뒤 계산한다. 2개 군집의 identity·swap 두 대응을 모두 비교하고 동점이면 identity를 택한다. set별 mapping, 두 대응의 일치 행 수, 선택 근거를 출력해 결과에 기록한다. 이 정렬은 품질 탐색용 share에만 적용하며 기존 ARI 계산 방식은 바꾸지 않는다.

IF는 각 set·seed의 train/follow-up score, 고정 규칙에 따른 문턱·후보 수·비율, 날짜별 후보 비율을 기록한다. 같은 set의 seed 쌍에 대해 전체 행 score Spearman ρ와 후보 집합 Jaccard를 구하고 median/min을 표시한다. 모든 seed 42를 FS0 seed 42와 비교해 score Spearman ρ, 후보 교집합 건수·Jaccard, 유지·탈락·신규 후보 행을 기록한다. 변경 후보의 Raw·proxy 조건은 기술통계로 설명한다. 공집합 Jaccard는 양쪽 모두 공집합일 때 1, 한쪽만 공집합이면 0으로 정의한다.

비교표에는 feature 수, silhouette, K seed ARI median/min, IF seed score ρ median/min, IF seed candidate Jaccard median/min, FS0 대비 score ρ·candidate Jaccard, train/follow-up candidate %, 바뀐 후보의 특징, redundancy 진단, 해석 장점·한계를 모두 둔다. Notebook은 **자동 우승 모델을 고르지 않는다**. 최종 후보는 재현성·seed 안정성·해석 가능성·간결성을 함께 본 후 사람이 검토한다. 파생변수의 추가 가치가 분명하지 않으면 FS0 유지가 허용된다.

각 set·seed의 train 점수 95% 분위수로 문턱을 정하므로 `train_candidate_pct`는 구조상 대략 5%가 된다(동점 때문에 정확히 5%는 아닐 수 있음). 비교표에는 **문턱 규칙 sanity check**로만 남기며 모델 우열 판단 근거로 사용하지 않는다. NBJ-005 고정 문턱을 쓰는 FS0 seed 42도 재현 확인용이다.

## 필수 NBJ-005 regression gate

다른 set의 fit 전에 `FS0_RAW4, seed=42`를 NBJ-005 설정대로 다시 fit한다. NBJ-005 저장 행별 결과의 **전체 11,939행**과 Excel 행 키·분할, cluster ID, 중심거리, IF score, candidate를 대조한다. train/follow-up 8,470/3,469행, train 95% `linear` 분위수와 metadata 문턱, 날짜별 cluster 건수·IF 후보 건수도 대조한다. 이 gate 실패 시 즉시 예외로 중단하고 physics 비교를 실행하지 않는다. 실패한 값을 맞추기 위해 설정을 조정하지 않는다.

NBJ-005의 실수 허용오차 그대로 `rtol=1e-10`, `atol=1e-12` (`np.allclose`, 반올림 전 계산값과 저장 CSV 비교)를 사용한다. ID·분할·cluster·flag·건수는 **exact**다. threshold 계산값은 허용오차 내에서 NBJ-005 문턱과 맞아야 하며 FS0 후보 판정에는 저장된 고정 문턱을 쓴다. CSV 저장 정밀도로 인한 차이와 이산 출력 불일치를 구분해 기록한다.

어떤 모델 fit보다 먼저 실제 `sys.executable`과 `PYTHONPATH`가 NBJ-005 metadata의 `python_executable`·`pythonpath`와 각각 **문자열로 정확히 일치**하는지 확인한다. 기존 Python·패키지 버전 검사도 유지한다. 환경이 다르면 중단하며 설치, `.venv` 재생성, 보안정책 변경으로 맞추지 않는다.

## 날짜별 품질 비교와 금지 해석

원본 `result`에 명시적 검사·생산 수량 분모가 없으므로 **실제 defect rate를 계산하지 않는다**. 기존의 실제 날짜별 기록이 있는 날만 후보 비율·`aligned_cluster1_share`·median score와 기재 불량 건수 또는 **`defects_per_1000_raw_records = 1000 × 기재 불량 건수 / 그날 Raw 행 수`**의 Spearman ρ를 탐색적으로 계산한다. 이 보조 지표는 불량률이나 불량품 비율이 아니다. 실행 시 NBJ-004 `quality_daily.csv`의 원본 날짜·행 수·기재 건수와 다시 대조한다. 3/27 미기록은 0으로 채우지 않고, 3/31은 유형이 2개만 기록돼 부분합이므로 완전한 3유형 합계가 필요한 비교에서는 제외한다. 날짜 수가 적고 행별 정답이 없으며 반복 공정조건이 있어 품질 상관은 최종 선택의 단독·주 기준이 아니다. `accuracy`, `precision`, `recall`, `F1`, `ROC-AUC` 같은 지도 지표를 만들지 않는다. 군집·candidate를 정상/불량이나 불량확률로 표현하지 않는다.
