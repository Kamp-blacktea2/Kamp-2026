## 2. 이번 실험이 필요한 이유

NBJ-004는 군집과 희소성 점수를 분석했지만, 현재 폴더에는 행별 CSV와 그림만 있고 재로드할 학습 모델·scaler 파일은 없다. 실제 코드도 학습 객체를 직렬화하지 않는다. 따라서 새 입력에 같은 기준을 적용하려면 전처리, 모델, 점수 방향, 문턱과 참조 분포를 함께 보존하는 구조가 필요하다.

이번 변경은 모델의 분석 성능 개선이 아니라 학습과 inference의 분리, 저장·재로드, 입력 계약 및 재현성 검증이다. 기존 데이터 재생은 소프트웨어 동작 검증이며 새로운 현장 데이터에 대한 일반화 검증이 아니다.

## 3. NBJ-004와의 관계

Baseline은 NBJ-004의 **StandardScaler + 주 seed 모델**과 저장된 행별 결과다. 사용자 확인 후 동일 데이터·행 순서·환경·설정으로 해당 모델만 다시 fit하여 직렬화할 계획이다. 존재하지 않는 저장 모델을 재사용한다고 쓰지 않는다.

K는 기존 선택값을 고정한다. K 후보 재탐색, 보조 seed 비교, RobustScaler·중복 제거 민감도, AE 학습·교차분석, Force/Current/Rolling 재분석, 날짜별 품질 상관 및 cluster 내부 IF는 이번 범위에 넣지 않는다. 이전 분석 전체를 호출하는 방식으로 구현하지 않는다.

NBJ-004의 군집은 Elbow 보조 기준과 상충한 **잠정 조건 분할**이다. 이 상태를 모델 metadata에도 남긴다. 기존 AE 비교가 자료 부재로 보류됐다는 사실도 유지하며 이번 prototype으로 해결된 것으로 취급하지 않는다.

## 5. 가설

NBJ-004의 데이터 분할, 전처리와 모델 설정을 고정하면 같은 입력의 반복 inference 및 저장 전·재로드 후 결과가 동일하고, NBJ-004의 핵심 행별 K-Means / IF 결과도 재현될 것이다.

이는 pipeline 재현성 가설이다. 실제 불량 예측 성능이나 군집의 물리적 운전모드 여부를 검증하는 가설은 아니다. 판정은 아래 검증 항목별 일치·불일치·검증 불가로 기록하며 임의의 성공 비율을 만들지 않는다.

## 7. 입력 feature

**[NBJ-004에서 이미 고정된 조건]** 입력은 아래 순서의 4개 열이다. 출처는 실제 코드 `COLS` 및 NBJ-004 계획의 변수 정의다.

| 순서 | 원본 열 이름 | 출력 이름 / 단위 |
|---|---|---|
| 첫째 | `weld force(bar)` | `force_bar` / bar |
| 둘째 | `weld current(kA)` | `current_kA` / kA |
| 셋째 | `weld Voltage(v)` | `voltage_V` / V |
| 넷째 | `weld time(ms)` | `weld_time_ms` / ms |

날짜·입력 ID는 metadata로 분리한다. idx, 날짜, 품번, 두께, 실제 불량 집계 및 파생변수를 모델 입력에 넣지 않는다. 단위 변환을 자동 추측하지 않는다.

## 8. 전처리

- **[NBJ-004에서 이미 고정된 조건]** K-Means와 IF는 각각 동일 train에 `StandardScaler()`를 fit한다. 기본 `with_mean=True`, `with_std=True`를 명시하여 보존한다. 기존 코드처럼 모델별 scaler를 별도로 저장하고 학습 속성의 일치 여부도 기록한다.
- 원본 중복, 높은 Force 및 소수 Weld Time을 그대로 유지한다. 반올림·정수화·결측 대치·이상치 제거·clipping을 하지 않는다.
- inference는 저장된 scaler의 `transform`만 사용한다. follow-up·새 입력으로 `fit`, `fit_transform`, 참조 분포 갱신을 하지 않는다.
- **[NBJ-005에서 새로 사전고정한 탐색 기준]** 이름 기반 입력을 저장한 feature 순서로 정렬한다. 이름이 없어서 순서가 모호한 입력, 필수 센서 누락, 비수치·결측·무한대, 단위 불일치는 오류로 반환하고 score를 만들지 않는다. metadata는 허용된 필드로 분리한다.
- 가이드 수집 범위나 기존 데이터 최솟값·최댓값을 새로운 합격선 또는 자동 제외 기준으로 삼지 않는다. 범위 밖의 유효한 수치에도 모델은 값을 반환할 수 있으나 그 입력의 현장 타당성은 검증되지 않았다.

## 9. K-Means 방법

아래 설정 전체는 **[NBJ-004에서 이미 고정된 조건]**이다. 근거: `kmeans` 함수 및 manifest의 `K.used_K`.

| 항목 | 고정값 |
|---|---|
| K / 주 seed | `n_clusters=2`, `random_state=42` |
| 초기화 / 반복 | `init='k-means++'`, `n_init=20`, `max_iter=300` |
| 수렴 / 알고리즘 | `tol=1e-4`, `algorithm='lloyd'` |
| 학습 입력 | K-Means용 train-fit StandardScaler가 변환한 train |

저장 모델의 `predict`로 cluster ID를 반환한다. 중심거리는 **표준화 공간에서 배정된 중심까지의 유클리드 거리** `norm(z - centers[cluster])`이며 무차원이다. 원단위 센서 거리나 불량 확률이 아니다. 군집 번호에는 정상/불량 의미를 부여하지 않는다.

K 선택을 다시 수행하지 않고 기존 행별 배정·중심거리, 학습 inertia, 군집 수와 날짜별 비율을 대조한다. Silhouette와 Elbow는 이전 선택의 근거로만 참조하며 재탐색하지 않는다.

## 10. Isolation Forest 방법

아래 설정 전체는 **[NBJ-004에서 이미 고정된 조건]**이다. 근거: `isolation_forest` 함수 및 manifest의 주 seed 항목.

| 항목 | 고정값 |
|---|---|
| 숲 / 표본 | `n_estimators=300`, `max_samples=min(256, n_train)=256` |
| feature / bootstrap | `max_features=1.0`, `bootstrap=False` |
| contamination / seed / 병렬 | `contamination='auto'`, `random_state=42`, `n_jobs=4` |
| 주 점수 | `s = -model.score_samples(if_scaler.transform(X))`, 클수록 희소 |
| 주 문턱 정의 | train 점수의 95% 분위수, `np.quantile(..., .95, method='linear')` |
| 고정 주 문턱 | manifest의 전체 정밀도 `0.6079581703468012` |
| candidate | `s >= 고정 주 문턱`; 동점을 포함 |

inference에는 기존 manifest의 주 문턱을 저장하여 사용한다. 같은 설정으로 재구성한 train 점수에서 분위수를 재계산하는 것은 문턱 재현 확인용이다. 값이 다르면 허용오차·행별 flag를 검사하고 원인을 기록하며 문턱을 몰래 교체하지 않는다. sklearn 기본 `predict`나 `decision_function`의 판정으로 대체하지 않는다.

**[NBJ-004에서 이미 고정된 조건]** 이전 99% 민감도 문턱 `0.6681064037197512`는 출처 metadata에만 보존한다. 이번 주 candidate를 대체하거나 새 민감도 실험을 수행하지 않는다. 불량 기록으로 contamination·문턱·모델을 조정하지 않는다.

**[NBJ-005에서 새로 사전고정한 탐색 기준]** train reference anomaly percentile은 `100 × count(train_score <= s) / n_train`으로 정한다. 동점은 상단 누적순위로 통일한다. 정렬한 전체 train 점수를 중복 포함 저장하여 `searchsorted(..., side='right')`로 계산한다. 참조 최솟값 미만은 0, 최댓값 이상은 100이며 단위는 percentile(%)이다. 이는 분포 내 순위 표시이고 불량 확률이 아니다. percentile에 별도 cutoff를 적용하지 않으며 주 candidate는 원래 score 문턱으로만 결정한다. 동점과 분위수 보간 때문에 percentile 기준으로 flag를 바꾸지 않는다.

## 11. 모델 저장 및 inference 구조

아래는 추후 구현 설계이며 현재 파일을 생성하거나 실행하지 않는다.

- 학습·저장 진입점: 원본 식별 확인 → train/follow-up 마스크 확인 → 모델별 scaler와 고정 주 모델 fit → 기존 결과 대조 → 모델 bundle 저장.
- inference 진입점: bundle 로드 → feature·단위 검증 → 모델별 transform → 군집·거리·IF score → 고정 train reference percentile·candidate 반환. 단일 행과 행 묶음을 지원한다.
- 예정 bundle `outputs/models/pipeline.joblib`: 모델별 fitted scaler, K-Means, IF, 고정 feature 순서·단위, 원래 문턱과 비교 연산, 정렬 train 점수, seed·설정·잠정 군집 상태를 함께 저장한다.
- 예정 `outputs/models/metadata.json`: 입력 해시·시트·분할·행 순서 식별, 코드 해시, 실제 실행 명령, 패키지 버전·스레드 설정, 모델 파일 해시, 점수·거리·percentile 정의와 검증 상태를 기록한다. 저장 형식·의존성은 공용 환경에서 제공되는 것을 사용한다.
- 계획 환경은 NBJ-004 manifest의 버전이며 수치는 **[NBJ-004에서 이미 고정된 조건]**: Python 3.13.15, numpy 2.2.4, pandas 2.2.3, scikit-learn 1.6.1, CPU 4스레드. 코드의 OMP/MKL/OPENBLAS 설정도 유지한다. 직렬화 패키지 등 manifest에 없는 버전은 실행 전 공용 `.venv`에서 확인하여 기록할 TODO다.

| 행별 반환 필드 | 정의 |

| `input_id` | 기존 데이터는 원본 해시·시트·Excel 행 번호; 새 입력은 호출자가 제공한 추적 ID |

모델 로드 후 inference 경로에는 학습을 포함하지 않는다. 환경·원본·설정이 달라지면 동일 baseline으로 조용히 처리하지 않고 차이를 보고한다. NBJ-004와 다른 설정이 필요하면 이유를 계획에 반영하고 실행 전에 사용자 확인을 받는다.

## 12. 검증 방법

기존 CSV는 `save`에서 유효숫자 15자리로 기록했다(**[NBJ-004에서 이미 고정된 조건]**). 따라서 기존 CSV와의 실수 비교와 같은 객체의 저장·재로드 비교를 구분한다.

| 검증 | 비교 대상과 판단 |
|---|---|
| 반복 inference | 동일 환경·동일 bundle·동일 순서의 전체 기준 입력을 두 번 호출. metadata·ID·flag와 모든 실수 출력이 정확히 동일해야 함 |
| 저장·재로드 | 저장 직전과 새로 로드한 bundle에 같은 전체 기준 입력 적용. scaler 속성·중심·문턱·참조 점수 및 모든 출력이 정확히 동일해야 함 |
| feature 순서 | 이름 있는 입력의 열 순서를 바꿔도 정규 순서로 복원되어 같은 출력. 센서 누락·모호한 위치 입력은 오류이며 조용히 잘못된 순서로 계산하지 않음 |
| train 전처리 재사용 | scaler의 학습 평균·scale·학습행수를 train과 대조. inference 전후 scaler·모델·참조가 바뀌지 않는지 확인 |
| 데이터 분할 | 원본 키·날짜·train 마스크가 NBJ-004 행별 CSV와 모두 일치. 원본 순서와 분할별 행 수 일치 |
| K-Means 재현 | 모든 원본행의 ID·cluster ID, 군집별·날짜별 건수는 정확히 일치. 거리와 학습 inertia는 아래 실수 허용오차 적용 |
| IF 재현 | 주 seed의 모든 행 score와 재계산 문턱은 아래 실수 허용오차 적용. 고정 문턱 candidate 및 분할·날짜·군집별 후보 수는 정확히 일치 |
| percentile | 저장 train reference로 정의한 누적순위와 대조. 같은 score의 동점은 같은 percentile, score에 대해 비감소. 참조를 follow-up으로 재계산하지 않음 |
| 단일 행 / 묶음 | 원본의 첫 행과 문턱 바로 아래·같음·바로 위에 해당하는 관측 행을 이용해 단일/묶음 출력을 대조. 없는 동점 사례는 해당 없음으로 기록하고 가짜 센서 입력을 만들지 않음 |

**[NBJ-005에서 새로 사전고정한 탐색 기준]** 반복 횟수는 사용자 요구대로 2회다. 같은 환경의 반복·직렬화 전후 비교는 실수도 정확 일치(`rtol=0`, `atol=0`)를 요구한다. 기존 CSV의 연속값 및 단일/묶음 계산 비교에는 `abs(new - ref) <= 1e-12 + 1e-10 × abs(ref)`를 적용한다. 이는 CSV 저장 정밀도와 부동소수점 계산 차이를 위한 사전 공학적 허용오차이며 공식 품질 기준이나 실험으로 측정한 오차가 아니다. 정확 일치와 허용오차 내 일치를 따로 보고한다.

실수 허용오차 안이더라도 cluster ID·candidate가 달라지면 재현 실패로 기록한다. 순수 군집 번호 교환도 임의 정렬하여 완전 일치로 바꾸지 않는다. percentile은 기존 NBJ-004에 없는 신규 출력이므로 기존 결과 재현이라고 주장하지 않는다. 비교에는 반올림 전 값을 사용하고 최대 절대차·불일치 행 및 원인을 남긴다. 실패 후 seed·K·문턱·허용오차를 바꾸어 성공으로 만들지 않는다.

## 13. 필요한 표와 그래프

예정 표는 입력·환경·설정 대조표, 검증 항목별 일치 및 실수 차이 표, 행별 inference 결과, 분할별·날짜별 군집 수/비율, IF 후보 수/비율 및 score 요약이다. 원본 행 키로 기존 CSV와 연결하여 재현 여부를 확인한다.

최소 그림은 cluster별 센서 분포, 날짜별 cluster 비율, IF score 분포와 고정 문턱, cluster별 IF score 분포다. 센서는 bar/kA/V/ms, 비율은 %, score는 무차원으로 제목·축·범례에 표시한다. train/follow-up을 구분하고 모든 그림은 동일한 고정 inference 결과에서 만든다. PCA·t-SNE·UMAP 및 추가 상관 탐색은 계획하지 않는다.

## 15. 결과로 말할 수 있는 것

검증 통과 시 고정 기준으로 입력을 잠정 공정 cluster에 배정하고, 중심거리와 분포 기준 희소성 score·percentile·candidate를 재현 가능하게 반환한다고 말할 수 있다. 저장·재로드 일치와 NBJ-004 행별 결과 재현은 검증한 환경·자료 범위 안에서만 주장한다. cluster와 score는 공정 상태 설명 및 검토 우선순위를 위한 정보다.

## 16. 결과로 말할 수 없는 것

개별 제품의 실제 정상/불량, 불량 발생 확률, 센서의 품질 인과관계, Accuracy / Recall / F1 등의 실제 불량 분류 성능을 말할 수 없다. 낮은 score나 candidate 미선정도 정상 품질 보증이 아니다. 확정된 물리적 regime, 새로운 센서 조합에 대한 일반화, 현장 오경보율·경고 선행시간·실시간 처리 성능도 이번 검증만으로 확인되지 않는다.
