## 3. 실제 수행 내용

고정 네 변수 Force(bar), Current(kA), Voltage(V), Weld Time(ms)만 사용했다. train에만 각 모델용 `StandardScaler`를 별도로 fit하고 K-Means K=2 주 seed=42, IF 주 seed=42를 fit했다. IF 연속 score는 `-score_samples`, candidate는 NBJ-004의 고정 문턱 `0.6079581703468012` 이상이다. 중복·고 Force·소수 Weld Time 값을 유지했다.

모델별 scaler, 두 fitted 모델, feature 순서·단위, 고정 문턱, 중복 포함 정렬 train IF score 및 metadata를 저장했다. `infer`는 이름 있는 새 센서 입력을 고정 순서로 변환하여 군집 ID, 표준화 중심거리, 연속 IF score, train 누적순위 percentile 및 candidate 여부를 반환한다. 모든 후속 행에는 저장된 train scaler·문턱·참조만 적용했다.

## 4. 계획과 같았던 점

train/follow-up 경계, `StandardScaler()`의 기본 평균·표준편차, K-Means의 `n_clusters=2`, `init='k-means++'`, `n_init=20`, `max_iter=300`, `tol=1e-4`, `algorithm='lloyd'`, seed=42를 유지했다. IF는 `n_estimators=300`, `max_samples=256`, `max_features=1.0`, `bootstrap=False`, `contamination='auto'`, seed=42, `n_jobs=4`를 유지했다. 주 후보는 train score의 95% linear 분위수에서 고정한 NBJ-004 문턱으로 정했다. 허용오차는 계획대로 기존 CSV 비교에 `rtol=1e-10`, `atol=1e-12`; 반복·재로드 비교에 정확 일치를 사용했다.

K 재선택, 보조 seed, AE, Rolling, GMM, 새로운 feature 및 다른 팀원의 모델·산출물 사용은 수행하지 않았다.

## 5. 계획에서 달라진 점과 이유

실행 파일만 위의 허용된 동일 버전 CPython으로 바꿨다. 프로젝트 `.venv\Scripts\python.exe`는 OS 정책으로 실행할 수 없지만, 사전점검에서 모든 분석 패키지를 기존 `.venv\Lib\site-packages`에서 정확한 버전으로 로드함을 확인했다. 모델 설정·feature·split·threshold·허용오차는 바꾸지 않았다.

첫 성공 실행 후 `metadata.json`의 실행 명령이 차단된 `.venv` 실행 파일을 가리키는 **기록 오류**를 발견했다. `pipeline.py`의 metadata 기록 부분만 실제 `sys.executable`·`PYTHONPATH`·사전점검 기록을 남기도록 수정하고 같은 고정 조건으로 재실행했다. 아래 수치와 산출물은 이 최종 재실행 결과다.

| 구간 | Cluster 0 | Cluster 1 |
|---|---:|---:|
| train | 7,639 | 831 |
| follow-up | 3,192 | 277 |
| 전체 | 10,831 | 1,108 |

학습 inertia는 **24060.812186379928**로 NBJ-004 CSV의 **24060.8121863799**와 사전 허용오차 안이다(절대차 약 `2.91e-11`). 전체 행 중심거리의 CSV 대비 최대 절대차는 **`4.80e-14`**이며 허용오차 밖 행은 없다. K=2는 NBJ-004에서 Elbow 보조 기준과 상충한 **잠정 조건 분할**이라는 해석을 유지한다.

## 9. 반복 inference 검증

동일 bundle과 전체 **11,939행**을 같은 순서로 두 번 inference한 결과, metadata·센서 원값·군집·거리·score·percentile·candidate **모든 출력이 정확히 일치**했다. 이름 있는 센서 열의 순서를 바꾼 입력도 전체 출력이 정확히 같았다. 필수 센서 누락, 모호한 위치 입력, 비유한 수치 입력은 지정대로 거절했다. 두 scaler의 학습 평균·scale·학습행수는 train 자료와 일치했고 서로 같은 train 통계를 가졌다.

## 10. 저장·reload 검증

저장 직전 bundle과 `pipeline.joblib` 재로드 bundle의 전체 inference 출력이 정확히 일치했다. feature·단위·문턱·seed·잠정 군집 상태, 각 scaler의 평균·분산·scale·학습행수, K 중심, 정렬 train IF score reference도 정확히 일치했다. inference 이후 참조 점수는 바뀌지 않았다.

**지지 (계획한 재현성 범위).** 반복 inference와 저장·재로드 출력은 정확히 같고, NBJ-004의 cluster ID·candidate는 전체 행에서 정확히 같으며 거리·연속 score·inertia는 고정 허용오차 안에서 재현됐다. [verification.json](outputs/verification.json)의 판정형 **65항목 모두 통과, 실패 0항목**이다. 이 판정은 실제 불량 예측 성능에 대한 가설 판정이 아니다.

## 15. 결과가 의미하는 것

고정된 네 센서 입력에 대해 잠정 공정 cluster ID·중심거리와 IF 희소성 score·train 기준 percentile·candidate를 같은 규칙으로 반복 제공할 수 있음을 확인했다. 모델 객체와 전처리·참조를 저장·재로드해도 이번 자료·환경의 출력이 유지됐다. 기존 관측 조건을 replay한 재현성 결과다.

## 16. 결과만으로 말할 수 없는 것

개별 제품의 정상/불량, 불량 확률, 실제 불량 분류 Accuracy/Recall/F1, 센서와 품질의 인과관계, 새로운 날짜·새 조합에 대한 일반화 및 현장 경고 성능은 판단할 수 없다. 군집 번호 자체에 품질 의미가 없고, candidate 미선정도 정상 품질 보증이 아니다.

## 17. 오류와 실패

이전 단계에서는 프로젝트 공용 `.venv\Scripts\python.exe` 직접 실행과 uv를 통한 동일 파일 실행이 Windows Application Control **OS error 4551**로 차단되어 부분완료로 기록했다. Code Integrity 이벤트는 해당 파일이 엔터프라이즈 서명 수준을 충족하지 못했거나 정책을 위반했다고 기록했다. 이번에는 정책을 바꾸지 않고 사용자 지정의 실행 가능한 CPython과 기존 `.venv` 패키지 경로를 사용했다.

이번 실행 전 인라인 점검 명령은 PowerShell 인용 처리로 구문 오류가 나서 pipeline이 시작되지 않았다. 이를 별도 `preflight.py`로 기록한 후 정상 통과했다. 첫 성공 실행의 metadata 실행 경로 오류는 5절처럼 수정하고 재실행했다. 최종 실행의 모델·검증 오류 및 NBJ-004 불일치는 **없었다**. 문턱과 동일한 score의 관측 행은 없어 그 경계 사례만 해당 없음이다.
