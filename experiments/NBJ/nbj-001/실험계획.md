## 질문

KAMP `05. Guidebook_Welding.pdf`의 AutoEncoder 방법을 현재 제공된 원본 Excel에 적용하면, 학습·평가 구간의 복원오차와 이상치 **후보**가 어떻게 나타나는가?

## 가설

네 센서값을 복원하도록 학습한 모델은 일부 행에 큰 복원오차를 줄 수 있다. 어느 날짜·공정조건에 후보가 나타날지는 계산 전 확정하지 않는다. 제품별 품질 정답이 없으므로 후보 수가 실제 불량 수와 같을 것이라는 가설은 세우지 않는다.

## Baseline과 비교 범위

가이드 PDF 26~33쪽의 네 변수, Min-Max scaling, 앞 8,470행 Train·뒤 3,469행 Test, 4→3→2→3→4 AutoEncoder, 학습 오차 평균+8×표준편차를 **방법의 견본**으로 삼는다. 가이드가 보고한 수치와 같아야 실험이 성공했다고 판단하지 않는다. 가이드의 표·설명·코드가 불일치할 때는 실제 선택을 결과서에 기록한다.

이 실험은 기준 모델 재현이며 02의 날짜별 불량 기록 연관성, 03의 rolling 변동성, 제품별 분류는 포함하지 않는다.

## 변경할 요소

새 모델 성능을 높이기 위한 탐색 변수는 없다. 실행 재현을 위해 가이드에 명시되지 않은 난수 seed `42`, CPU·계산 스레드 1개를 고정한다. PDF의 테스트 코드가 `train_data`를 순회하는 부분은 **실제 Test 평가를 위해 `test_data`를 순회**하도록 명시적으로 바로잡고 결과서에서 차이를 보고한다. 실행 환경에서 scikit-learn의 SciPy 의존 DLL을 사용할 수 없어, 동일한 Min-Max 수식을 NumPy로 계산한다.

## 고정할 요소

| 항목 | 기준 |
|---|---|
| 입력 | Force (bar), Current (kA), Voltage (V), Weld Time (ms) 네 변수만 |
| 행 | 원본 `Raw data` 11,939행을 원래 Excel 행 순서로 사용; 센서 결측·중복을 임의 삭제하지 않음 |
| Scaling | 네 변수 각각 전체 11,939행의 최소·최대로 `(값−최소)/(최대−최소)` 계산 |
| 분할 | 앞 8,470행 Train, 뒤 3,469행 Test; Validation 없음 |
| 모델 | Linear `4→3→2→3→4`, 중간층 RReLU, 마지막 Linear 출력 |
| 학습 | Adam, 학습률 `0.01`, batch `64`, epoch `50`, MSE 손실, Train batch 순서 shuffle |
| 행별 점수 | 네 변수의 복원 평균제곱오차(MSE) |

| 평가 상태 | 가이드 코드처럼 `model.train()` 상태에서 `no_grad()`로 Train→Test 순서 점수 계산; `eval()` 사용하지 않음 |

원본 순서대로 분할한 뒤 Train과 Test의 오차 분포·임계값 초과 수·Test 후보의 원단위 공정조건을 확인한다. 파일 내용 해시, 4개 변수 결측 여부, 행 수와 분할 수, 전체 코드 셀의 새 커널 실행을 검사한다.
