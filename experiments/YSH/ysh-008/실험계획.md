## 질문

**사전에 고정한 298행 반복 motif를 하나의 구조 변수로 두었을 때, YSH-007의 전역 밀도·component 내 이탈·조건부 열 편차와 저장소에서 재현 가능한 YSH-005 AE의 재구성 오차가 같은 상대위치와 변수를 가리키는가? 그리고 B의 높은 NLL과 기존 물리 screening 후보가 이 motif 자체와 motif 내 국소 편차 중 무엇을 반영하는가?**

세부 질문은 다음과 같다.

1. B–A 점수 차이가 repeat298 행을 분리한 후에도 유지되는가? 더 긴 parent 반복블록의 나머지를 B-nonrepeat에서 분리해도 같은 결론인가?
2. repeat298은 전역 밀도에서 희귀한 상태인가, 그 안에서 component 내 d²·조건부 z가 특히 큰 상대위치가 남는가?
3. AE candidate와 NLL/d²/조건부 z 후보가 같은 `relative_position` 구간에 모이는가?
4. 두 방법이 동시에 후보로 지목한 행에서 dominant variable도 같은가?
5. YSH-007의 `row_review_candidate`가 repeat298 공정상태 자체를 선별하는지, motif 내 상대적 꼬리를 선별하는지 구분할 수 있는가?
6. 같은 순서의 네 occurrence를 한 motif로 접었을 때도 공통 episode가 남는가?
7. 동일한 Raw4 motif 자체만으로 occurrence가 속한 날짜의 Result 변동을 설명할 수 있는가?

### AE 입력 계약과 실제 충족 상태

행 매핑의 주 키는 `excel_row`이다. Raw `idx`는 날짜마다 재시작하고 03-25/idx=1 충돌도 있으므로 단독 join 키로 쓰지 않는다. Raw4 값은 정확 반복 때문에 위치를 유일하게 정하지 못하므로 join 키가 아니다.

| 필드 | 필요도 | 처리 |
| --- | --- | --- |
| `excel_row` | 필수 | 헤더를 포함한 원본 Excel 행 번호. 중복·누락·범위를 감사한다. |
| `date` | 필수 | Raw `working time`과 일치해야 한다. |
| `original_row` 또는 `idx` | 선택 | 원본 정의가 문서화된 경우에만 교차 검사한다. 0-based 위치를 Excel 행으로 자동 변환하지 않는다. |
| `ae_total_error` | 008C 필수 | 점수 방향, 합/평균 정의, 입력 스케일을 함께 기록한다. |
| `ae_candidate` | 008C 필수 | 기존 AE에서 고정한 문턱을 그대로 사용하고 YSH-008에서 재조정하지 않는다. |
| `ae_error_F/I/V/t` | 008D 필수 | 변수별 error의 정의·스케일이 같은지 확인한다. 없으면 008D는 NA로 남긴다. |
| 모델·전처리·문턱 metadata | 필수 | feature 순서, scaler, 학습 날짜/행, seed, loss, threshold, 산출물 해시를 기록한다. |

실제 후속에서는 YSH-005 저장 reconstruction이 기존 모델의 명시적 행별 출력이므로, 그 모델 입력과 동일한 scaled 공간에서 feature별 squared error를 계산하고 정의·해시를 metadata에 기록했다. total/candidate는 기존 `row_scores.csv`와 정확히 일치했다. 동료 AE에 없는 열을 보간하거나 그 보고의 산출물인 것처럼 만들지는 않았다.

## 변경할 요소

- repeat298 소속 여부, occurrence ID, `relative_position=1..298`, 같은 motif 그룹을 기존 행별 산출물에 추가한다.
- 주 분석은 전체 A, B-repeat298-core, B-nonrepeat로 GMM 점수·component·기존 물리 후보를 분해한다. parent 감사가 가능하면 B-nonrepeat를 `parent-repeat-other`와 `outside-parent`로 다시 나눈 민감도를 추가한다.
- 기존 전역 physical screening 표지를 motif 위치에 재표현한다. 필요할 때만 motif 내부 상대 꼬리 표지를 별도 sensitivity로 두며, 이를 block-conditioned physical threshold라고 부르지 않는다.
- YSH-005 reference AE–GMM 행 표시·연속점수·dominant variable를 비교한다. 동료 AE 보고와는 분리한다.
- AE episode, 개별 GMM episode, 두 방법의 consensus episode를 각각 만든다. 방법 union은 주변 문맥을 보여주는 contextual envelope로만 둔다.

## 고정할 요소

- repeat298 시작행과 길이는 1879/4693/7803/10879, 298행으로 고정한다. 결과를 보고 블록 경계를 늘리거나 줄이지 않는다.
- YSH-007 Standard/full/K=6/seed42와 저장된 9회 LODO 점수를 고정한다. GMM과 scaler를 재학습하지 않는다.
- 동일 Raw4 occurrence의 LODO 점수 차이는 occurrence의 공정값 차이가 아니라, 보류 날짜마다 달라지는 reference model 차이로만 해석한다.
- AE 모델·점수·문턱은 YSH-005 seed42 정의를 그대로 사용하고 재학습·재튜닝·결과 기반 threshold 변경을 하지 않는다.
- 하나의 고정 모델·scaler로 각 행을 독립 처리하는 row-wise AE라면 동일 Raw4의 total·feature error와 candidate는 occurrence 간 같아야 한다. 이를 입력 sanity check로 먼저 확인한다.
- AE와 GMM 점수를 합친 ensemble anomaly score를 만들지 않는다.
- Result는 모든 motif·후보·문턱·열 선택을 완료한 후 일별 표에만 연결한다.
- `assigned_component`는 불량 유형이 아니고, `ae_candidate`와 각 GMM 표지도 실제 불량 라벨이 아니다.
- 행·occurrence·relative position·motif·episode 분모를 모든 표에 표시한다.

## 고정 후보 표시 정의

이 실험은 하나의 이상 정의로 합치지 않고 아래 표지를 따로 보고한다.

| 표지 | 사전 정의 | 해석 |
| --- | --- | --- |
| `gmm_nll_q90` | `global_nll_train_percentile >= 0.90` | 해당 날짜 제외 model train 분포 대비 전역 희소성 상위 10% 표지 |
| `gmm_d2_q90` | `mahalanobis_d2_train_percentile >= 0.90` | 배정 component 내 이탈 상위 10% 표지. YSH-007 잔차 후보 풀의 주 문턱과 맞춤 |
| `gmm_nll_q95`, `gmm_d2_q95` | 각 train percentile `>=0.95` | 민감도. 주 결론 선택에 사용하지 않음 |
| `conditional_z_2_5` | `max(abs(conditional_z_F/I/V/t)) >= 2.5` | YSH-007 후속의 고정 열별 조건부 편차 표지 |
| `physical_global_candidate` | 기존 `row_review_candidate` | 기존 물리 signature 중 하나 이상 + d² percentile≥0.90 또는 \|z\|최댓값≥2.5 |
| `ae_candidate` | YSH-005 seed42의 train mean + 8×population SD | YSH-008에서 문턱 재조정 없음 |

q90은 실제 불량률이 아니라 YSH-007에서 사용한 상위 10% 탐색 범위와 맞추기 위한 비교 표지다. 동점은 모두 포함하고 실제 표시 수를 남긴다.

## 검증 방법

### 008A. Repeat Block Audit

1. 네 시작행에서 298행씩을 가져와 Raw4 배열이 위치별로 정확히 같은지 원본으로 다시 확인한다.
2. occurrence별 `occurrence_id`, `date`, `excel_start/end`, `idx_start/end`, `safe_segment`, `relative_position`, Raw4를 매핑한다. `idx` 경계와 안전구간을 넘는 경우는 실패로 기록한다.
3. `exact_repeated_blocks.csv`에서 repeat298 전 구간을 포함하는 더 긴 exact block을 occurrence별로 찾는다. 여러 parent 후보나 서로 겹친 후보를 임의로 하나로 축약하지 않고 후보 ID·경계·길이를 모두 남긴다. 새 motif 발견 절차는 돌리지 않는다.
4. 확인된 포함 블록의 B 행 합집합을 `parent-repeat-union`으로 정의한다. `repeat298-core`, 합집합에서 core를 뺀 `parent-repeat-other`, 합집합 밖 B 행인 `outside-parent`를 서로 배타적으로 검산한다. 포함 관계를 재현할 수 없으면 두 민감도 집단은 `not_available`로 남긴다.
5. AE export가 있으면 `excel_row`를 1:1 join하고 날짜·선택적 idx·Raw4로 교차 감사한다. 일치하지 않는 행을 임의 이동하지 않는다.

### 008B. Block-conditioned GMM score decomposition

1. 주 분석은 전체 행을 A, B-repeat298-core, B-nonrepeat로 고정 분해한다. B 내 repeat 비중과 NLL/d²/posterior 분포, q90/q95 표지율을 제시한다.
2. 평균 점수에 대해 `(전체 B 평균 - B-nonrepeat 평균) / (전체 B 평균 - A 평균)`을 **repeat 제외 후 B–A 평균차 감소 비율**로 보조 계산한다. 분모가 0에 가깝거나 부호가 역전되면 NA와 원수치만 보고한다. p95와 후보율은 가산 분해가 아니므로 “설명된 비율”을 붙이지 않는다.
3. parent 포함 관계가 확인되면 B를 `repeat298-core` / `parent-repeat-other` / `outside-parent`로 나눈 분포와 후보율을 민감도로 제시한다. 특히 B-nonrepeat와 outside-parent의 B–A 차이를 함께 보여, parent의 나머지가 B-nonrepeat 비교군에 남긴 교란을 감사한다. 이 분할은 parent의 물리적 의미를 확정하지 않는다.
4. 고정 component 중첩은 `in_sample_scores.csv`로 서술하고 in-sample임을 명시한다. LODO component는 날짜별 번호와 프로필 지원을 함께 남기고 같은 물리 상태로 자동 병합하지 않는다.
5. 298개 상대위치별로 네 occurrence의 NLL, d², train percentile, max |conditional z|를 정렬하고 중앙값·범위·상위 표지 지지 횟수를 제시한다. 동일 Raw4에서 발생하는 occurrence별 LODO 차이는 입력 공정값 차이가 아니라 보류 날짜별 reference model·scaler가 만드는 점수 차이다. 이를 motif의 occurrence별 물리 변화나 품질 신호로 해석하지 않는다.

### 008C. AE–GMM row-level agreement

이 단계는 YSH-005의 저장 reconstruction과 기존 행 점수로 입력 계약을 충족한 뒤 실행했다. 동료 AE 254/298 보고의 재현 단계는 아니다.

1. agreement 전에 AE 실행 정의를 확인한다. 하나의 고정 모델·scaler로 각 행을 독립 처리한 AE라면, 동일 상대위치 네 occurrence의 `ae_total_error`, 각 feature error, `ae_candidate`가 저장 정밀도 범위에서 같아야 한다. 열별 최대–최소와 불일치 행을 sanity check로 남긴다. 설명되지 않는 차이가 있으면 agreement를 중단하고 매핑·모델·전처리를 먼저 감사한다. window/context 입력 또는 occurrence별 모델이면 동일성을 요구하지 않고 그 구조를 명시한다.
2. `ae_candidate`와 `gmm_nll_q90`, `gmm_d2_q90`, `conditional_z_2_5`, `physical_global_candidate`를 각각 2×2 표로 비교한다. GMM 표지끼리도 합치지 않는다.
3. 행 풀링 1,192개의 count/rate는 기술 표로만 둔다. 298개 상대위치마다 각 방법의 support를 0~4로 센 뒤, **주 binary positive는 support≥3/4**로 고정한다. support≥1/4는 permissive sensitivity, support=4/4는 strict sensitivity이며 결과에 따라 기준을 바꾸지 않는다.
4. 주 agreement 표는 AE와 각 GMM 표지의 support≥3/4 binary mask를 비교한다. sensitivity 표는 두 방법에 동일한 ≥1/4 또는 4/4 규칙을 적용한다. 동시에 선택된 occurrence 수는 별도 기술 열이며 위치 binary 정의를 대신하지 않는다.
5. 요약 지표는 각 표지의 선택 수·선택률, 교집, union, Jaccard, positive agreement, Cohen's kappa다. 유행률에 민감한 kappa만으로 일치를 판단하지 않는다.
6. `ae_total_error`와 NLL/d²/max |z|의 Spearman을 occurrence별·298위치 motif 중앙값 기준으로 나누어 보고한다. 정확 반복으로 인한 행 유의확률은 계산하지 않는다. 고정 row-wise AE의 occurrence별 오차가 같고 LODO GMM만 다르면, 그 차이는 reference model 차이임을 표에 명시한다.

### 008D. Dominant-variable agreement

이 단계는 `ae_error_F/I/V/t`가 모두 확인될 때만 실행한다.

- AE dominant variable은 같은 행의 네 feature error 중 최댓값의 열로 고정한다. 수치 동률은 `tie`, 누락은 NA로 남긴다.
- GMM dominant variable은 YSH-007에 저장된 `argmax(|conditional_z_F|, |conditional_z_I|, |conditional_z_V|, |conditional_z_t|)`로 고정하고 부호를 별도 열에 남긴다.
- full covariance Mahalanobis d²는 변수 간 cross-term을 포함하므로 각 열의 양의 기여로 임의 분해하지 않는다. AE dominant variable과 d² “기여열”을 비교했다고 쓰지 않는다.
- 주 분모는 AE와 비교 GMM 표지가 동시에 선택한 상대위치이다. 전체 repeat298을 민감도로 따로 제시한다.
- 4×4 confusion matrix, tie/NA 수, exact match rate, 최빈 AE/GMM 열을 제시하되, AE feature error와 z의 숫자 크기를 직접 비교하지 않는다.

### 008E. Existing physical screening overlap and motif-relative sensitivity

YSH-007의 `row_review_candidate`와 그 구성 threshold는 전역/LODO 참조 기준이며 block-conditioned threshold가 아니다. 주 분석은 이 기존 표지를 repeat298 상대위치에 **재표현**하는 것이다. 아래 motif-relative 표지는 결과가 필요할 때만 보는 sensitivity이며 기존 physical screening을 대체하지 않는다.

1. 기존 `row_review_candidate`와 각 물리 signature의 repeat298 중첩, occurrence support 0~4, 상대위치별 support≥3/4 주 표지와 ≥1/4·4/4 민감도를 보고한다.
2. 상대위치별 네 occurrence의 d²와 max |conditional z| 중앙값 profile을 기존 후보 위에 겹쳐, 기존 후보가 motif 전체 상태와 국소 꼬리 중 어디에 놓이는지 기술한다.
3. 선택적 민감도로만 298개 위치의 중앙값 경험적 q90 이상을 `motif_relative_d2_q90`, `motif_relative_z_q90`로 표시한다. 기존 물리 signature support≥3/4와 둘 중 하나를 함께 만족한 위치를 `motif_relative_physical_sensitivity`로 둔다. 동점은 모두 포함한다.
4. 기존 전역 후보와 motif-relative sensitivity의 유지/신규/제외 위치와 Jaccard를 보고한다. motif q90은 298개 안에서 정의상 꼬리를 만들 뿐이며 block-conditioned 품질 문턱, 성능 개선 또는 불량 교정으로 해석하지 않는다.

### 008F. Episode/motif aggregation

1. occurrence 안에서 각 방법의 연속 `relative_position`을 run-length로 요약하며 블록 경계를 넘겨 잇지 않는다. AE 후보로 `AE episode`를, NLL q90·d² q90·|z|·기존 physical 표지 각각으로 별도의 `GMM episode`를 만든다.
2. motif 수준에서도 support≥3/4 주 binary mask로 AE episode와 개별 GMM episode를 따로 만든다. ≥1/4와 4/4 mask의 episode는 민감도로만 둔다.
3. `AE∩GMM consensus episode`는 AE 주 mask와 **각 개별 GMM 주 mask의 교집합**에서 연속한 구간으로 정의한다. GMM 표지들을 먼저 합치거나, AE와 GMM의 union을 consensus로 부르지 않는다.
4. AE 또는 어느 GMM이든 표시한 위치의 union은 선택적으로 `contextual envelope`만 만든다. 이는 주변 검토 범위를 보여줄 뿐 episode 수, consensus 수, 오류 건수에 포함하지 않는다.
5. 각 방법별/consensus 구간에 시작·끝·길이·occurrence support·dominant variable 분포를 남긴다. 어떤 episode 수도 실제 오류 사건 수로 해석하지 않는다.

### 008G. Result exploratory association

- repeat298 존재는 B 날짜와 완전히 얽혀 있으므로 A/B 전체를 이용한 “블록 존재 ↔ Result” 상관은 계산하지 않는다.
- B occurrence별 motif 요약과 해당 날짜 Result를 한 표에 나란히 제시하되, Raw4 고유 정보와 reference-dependent GMM 점수를 분리한다. 03-27은 전 유형 NA, 03-31 유형3은 NA로 유지한다.
- 유형1/2의 관측 B는 03-25·03-31·04-03의 3일, 유형3은 03-25·04-03의 2일이므로 순위상관·유의확률·회귀를 제시하지 않는다.
- H6의 질문은 알려진 날짜 차이를 다시 확인하는 것이 아니라 **동일 Raw4 motif만으로 Result 변동을 설명할 정보가 있는가**이다. 고정 row-wise AE의 오차는 동일해야 하고 LODO GMM의 occurrence 차이는 reference model 차이이므로, 둘을 Raw4 자체의 occurrence별 설명변수로 사용하지 않는다.
- 동일 Raw4 밖의 맥락이나 블록–검사 연결 키 없이 Result가 달라 보이면 “repeat298 Raw4만으로는 날짜별 품질 변동을 설명할 수 없다”는 한계로 기술한다. 해당 블록에 Result가 배정된다거나 제품별 불량 원인이라고 주장하지 않는다.

실험의 성공은 특정 일치 결과가 나오는 것이 아니라, 다음 분기를 복제 계산 없이 판별할 수 있는 것이다.

## 데이터 누수와 독립성 점검

- YSH-007 LODO에서도 11,939행 중 11,741행(98.34%)의 Raw4가 다른 train 날짜에 존재한다. repeat298 네 occurrence 또한 학습–보류를 횡단하므로 날짜 제외 점수를 신규 공정 일자 성능으로 보고하지 않는다.
- YSH-005 AE의 train은 03-24~03-31 8,470행이므로 repeat298의 03-25/27/31 occurrence를 포함하고 04-03만 확인 구간이다. 이 agreement는 독립 외부 복제가 아니라 같은 자료에서의 모델 정의 비교다.
- 고정 row-wise AE에서 동일 Raw4의 오차가 다르면 anomaly 발견으로 해석하지 않고 입력·행 매핑·scaler·model version 오류 가능성을 먼저 처리한다. 반대로 LODO GMM의 차이는 설계상 reference model 차이이며 공정값 차이의 증거가 아니다.
- repeat298 반복 원인은 실제 공정 반복, 센서 양자화, 데이터 구성/복제 중 미확정이다. 네 occurrence를 네 개의 현장 재현성으로 표현하지 않는다.
- 동일 Raw4 행이 많으므로 값 조인을 금지하고 원본 위치를 유일 키로 쓴다. join 전후 행 수·유일성·누락을 검산한다.
- motif 내 q90은 298행 전체를 본 사후 순위이므로 온라인 탐지·미래 예측으로 소개하지 않는다.
- Result는 모델·후보·변수·threshold를 고정한 후에만 연결하고, 비교가 좋아지도록 설정을 바꾸지 않는다.
