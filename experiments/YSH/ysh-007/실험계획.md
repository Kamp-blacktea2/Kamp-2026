## 질문

**현재 용접 Raw 데이터가 한 가지 공정 분포보다 여러 공정 regime로 설명되는가? 두 regime를 모두 정상 공정의 후보로 놓은 GMM에서 벗어나는 정도와 방향이 날짜별로 어떤 구조를 보이며, 그 구조가 Result의 유형별 일별 기록과 탐색적으로 연결되는가?**

단일 GMM component를 곧바로 정상/불량으로 나누지 않는다. Raw 한 행의 제품·Spot·품질 라벨이 확인되지 않았으므로 불량 분류 정확도나 제품 불량 수를 산출하는 실험이 아니다.

## 변경할 요소

- GMM component 수 K=1~6, covariance_type=full/diag, seed=17/42/2026. 주 전처리는 StandardScaler, RobustScaler는 사전 민감도다. H1의 가압력 지배 여부를 보기 위해 같은 고정 설정으로 I/V/t만 쓰는 분석을 한 번 더 수행한다.

- 원본 행 가중치, 날짜 내 unique4 가중치, 긴 정확 반복 후행 출현 제외 조건을 비교한다. controlled100은 날짜 지원이 크게 줄어드는 강한 민감도다.
- Result 비교는 관측값만 사용하는 주 분석과 NA를 0으로 둔 **가상 시나리오**를 분리한다.

## 검증 방법

### 1. 날짜·반복 구조 감사 (원안 YSH-007A)

날짜 9개의 Raw4 분포, F>3bar 비중, 고유4 조합과 정확 반복 피복을 전수 표로 고정한다. A/B 조성 차이는 먼저 관측치로 기록하고 실제 두 설비·두 제품·양품/불량을 뜻한다고 보지 않는다. 그림은 날짜별 네 변수 분포를 사용하되 모든 핵심 수치와 날짜별 분모를 표에도 남긴다.

### 2. 고정 날짜 보류 분할과 GMM 선택 (원안 YSH-007B)

행 random split은 사용하지 않는다. 사용자 원안의 5개 fold를 그대로 고정한다. 각 fold는 validation 1일, test 1일, 나머지 7일 train이며 train의 A:B 날짜 수는 모두 4:3이다.

| fold | validation | test | train |
| --- | --- | --- | --- |
| 1 | 2020-03-24 | 2020-03-25 | 나머지 7일 |
| 2 | 2020-03-25 | 2020-03-26 | 나머지 7일 |
| 3 | 2020-03-26 | 2020-03-27 | 나머지 7일 |
| 4 | 2020-03-27 | 2020-03-30 | 나머지 7일 |
| 5 | 2020-03-30 | 2020-03-31 | 나머지 7일 |

scaler와 GMM은 fold별 train에만 fit한다. validation/test에는 transform·predict·score만 적용한다. StandardScaler×K1~6×full/diag×3 seed를 주 격자로 실행하고 RobustScaler는 같은 격자의 민감도다. component 소실, 작은 weight, 공분산 퇴화, 수렴 경고·실패 fold는 삭제하지 않고 기록한다. reg_covar·max_iter·n_init 및 seed는 실행 전에 config에 고정한다.

각 후보 K·scaler·covariance_type·기타 하이퍼파라미터에 대해 **각 validation 날짜의 행당 평균 로그밀도를 세 seed에 걸쳐 평균한 뒤, 5개 날짜를 동일 가중치로 평균**하여 전역 설정 하나를 선택한다. 주 선택 순서는 이 평균(높을수록 우선) → 5개 train BIC의 fold별 요약 → seed/fold·component profile 안정성이다. seed 42를 최종 날짜별 scoring의 주 실행 seed로 사전 고정하고 17·2026은 안정성 진단에 사용한다. 각 fold의 best K는 진단용으로만 저장하고 fold별 최종 K로 사용하지 않는다. AIC와 hard label silhouette는 보조다. K=1의 silhouette는 NA다. 다른 scaler의 로그밀도와 BIC를 비교할 때는 Jacobian을 반영해 원 Raw 공간으로 환산한다. test 점수는 선택 뒤 기록하며 K·scale·feature를 바꾸는 데 쓰지 않는다.

이 fold들은 날짜 단위 보류이지만 train에 validation/test보다 늦은 날짜가 들어간다. 또한 여러 fold에서 같은 날짜가 train/validation/test로 다시 등장하고 긴 정확 궤적이 날짜를 넘는다. 그러므로 **미래 기간 예측 검증이나 독립 최종 test**로 보고하지 않는다. test log-likelihood는 이 설계에서의 보류 날짜 진단값이다. 4/2·4/3·4/7은 이 5개 fold에서 보류되지 않는다는 coverage도 명시한다.

### 3. 최종 날짜별 Leave-One-Day-Out scoring

5개 validation 날짜의 평균으로 설정을 전역 선택한 뒤 K·scaler·covariance_type·regularization·seed 등 모든 설정을 고정한다. **9개 날짜를 한 번씩 완전히 제외**하고 나머지 8일에 scaler/GMM을 새로 fit한다. 제외한 날짜에는 transform·posterior·score만 적용한다. 이 9회에서 K나 다른 설정을 다시 선택하지 않으며 행별 원본 위치와 train/held-out 날짜를 저장한다.

Result 일별 연관의 주 이상 점수는 이 LODO 결과를 쓴다. 날짜마다 fit된 모델이 다르므로 원 Raw 공간 점수와 함께 해당 train 점수 분포에서의 분위 위치를 저장해 날짜 비교의 척도를 확인한다. 전체 9일에 재적합한 점수는 별도의 **in-sample 서술**로만 둔다. 잔차 패턴도 설정·후보 풀 정의가 고정되고 지원 수가 충분하며, fold 간 pattern을 원 단위 profile로 대응시킬 수 있으면 LODO 방식으로 계산한다. 그렇지 않으면 Result와의 주 연관에서 제외하고 사용 가능한 fold·날짜 범위를 명시한다.

이 단계에서 각 날짜의 행은 해당 회차의 model fit에서 빠진다. 그러나 하이퍼파라미터는 앞선 5개 fold에서 이 9일을 활용해 선택됐고 정확 반복 궤적도 날짜를 넘는다. 따라서 LODO는 **날짜별 cross-fitted scoring**이며 완전히 미관측인 새 생산일에 대한 독립 일반화 검증은 아니다.

### 4. Component와 이상 점수 분포 (원안 YSH-007C)

선택된 설정에서 component label permutation을 원시 단위 평균·profile로 맞춘 뒤 날짜별 평균 posterior, hard 할당 비율, 최대 posterior, 정규화 entropy 및 dominant component를 기록한다. entropy는 K>1에서 −Σ p_k log(p_k)/log(K), K=1에서는 0으로 정의한다. 학습자료에서 설명할 때는 in-sample, 보류 날짜에서 설명할 때는 held-out을 분리한다. 전체 자료 재적합을 날짜 9개 설명에 사용한다면 **서술용 in-sample 모델**로 표시한다.

각 행의 global_nll = −log p_mix(x)를 계산한다. 배정 component k는 최대 posterior로 정하고 mahalanobis_d2 = (x−μ_k)ᵀΣ_k⁻¹(x−μ_k)를 계산한다. 이는 해당 component 안의 거리이지 불량 확률이 아니다. score 비교는 동일한 원 Raw 공간·동일한 방향에서 수행한다. 날짜별 count, 평균, 중앙값, 표준편차, p75/p90/p95/p99, max, IQR 및 원본 Excel 행 위치를 저장한다. train/validation/test, A/B, 정확 반복 소속을 구분한다.

이번 단계의 주 결과는 **분포**다. Result 수에 맞춘 binary threshold·anomaly 행 개수·실제 불량제품 개수는 만들지 않는다. 연속 high-score episode는 후속 문턱 실험의 후보 개념으로만 남기며 현재 완료 조건에 넣지 않는다.

### 5. 잔차 방향 탐색 (원안 YSH-007D)

기본 GMM에서 각 행을 배정 component의 평균과 비교하고, 공분산을 반영한 whitened residual을 주 표현으로 사용한다. 공분산 역제곱근의 수치 안정화 방식은 train 자료에서 고정·기록하고, 같은 모델·변환을 보류 날짜에 적용한다. 원 단위 잔차도 해석용으로 보존한다.

잔차 GMM이 모든 정상 잔차만 다시 군집화하지 않도록, **주 후보 풀은 전체 train의 mahalanobis_d2 상위 10%**로 고정한다. 동률은 모두 포함하고 실제 후보 수를 기록한다. 이것은 불량 판정 문턱이 아니라 방향 분석의 범위다. 배정 component별로 train mahalanobis_d2 상위 10%를 뽑아 합친 풀을 민감도 조건으로 둔다. 각 component의 train 지원 수·문턱·선택 수를 저장하고, 작은 component에서 비교가 불가능하면 NA로 남긴다.

주 후보 풀만으로 K_error=2~5를 train에서 fit하고, validation 후보에는 train에서 정한 점수 문턱과 잔차 변환을 적용한다. K_error 선택에는 train BIC·validation 후보 잔차의 평균 로그밀도·seed 안정성을 함께 사용한다. K_error=3은 별도 표로 보되 최적값이나 불량 3종의 정답으로 채택하지 않는다. 민감도 풀에서는 **선택된 K_error·covariance·seed를 고정**하고 잔차 GMM을 다시 fit하여 후보 풀 변경의 효과만 비교한다. 두 조건의 잔차 profile 원 단위 방향, 후보/전체 행 분모, 날짜별 pattern share와 seed/fold 지원 범위를 함께 기록한다.

### 6. Result 일별 연관과 regime 혼동 감사 (원안 YSH-007E)

GMM·점수·잔차 패턴을 Result 없이 확정한 뒤 날짜별 집계 표에만 연결한다. 유형1/2는 관측 8일, 유형3은 7일이다. 2020-03-27의 전 유형 미기록과 2020-03-31의 유형3 미기록은 주 분석에서 NA다. 2020-04-07 유형1의 명시적 0은 관측 0으로 남긴다. 유형별 기재 건수와 1000×건수/Raw 기록 수를 따로 표시하되 후자는 제품 불량률이 아니다.

주 분석은 관측 날짜만으로 방향·순위·날짜 하나 제외 결과를 기술한다. 연관 표를 전체 관측 날짜와 A 날짜, B 날짜로 분리해 A/B 분포 차이만으로 생긴 관계인지 살핀다. 유형1/2에서 B의 관측 날짜는 3일, 유형3에서 B는 2일뿐이므로 하위 그룹의 상관계수는 지원 수를 밝히고 과대해석하지 않는다. 날짜별 방향과 날짜 하나 제외 민감도를 우선한다. 사용자 원안의 weak-normal/weak-absence는 **민감도 가정**으로만 시행한다: 미기록을 0으로 치환한 가상 시나리오를 별도 표에 저장한다. 미기록 자체가 실제 정상/부재의 증거라는 주장은 하지 않는다. 주 결과와 방향이 같아도 독립 검증으로 승격하지 않는다.

### 7. 물리적 해석 검토와 반복 민감도 (원안 YSH-007F)

잔차 패턴의 Raw 단위 F/I/V/t 방향을 먼저 고정하고, 그 후 공식 공정 설명과 신뢰 가능한 Spot 용접 자료에서 가능한 메커니즘을 검토한다. 외부 자료는 질적 해석에만 사용하고 학습·전이·문턱 선정에 쓰지 않는다. 전극 마모·접촉저항·냉각 등의 미관측 요인을 특정 행의 원인으로 확정하지 않는다.

all 주 결과와 날짜 내 unique4 가중치, controlled100을 비교한다. controlled100은 2,416행·4날짜만 남고 날짜별 A/B·Result 분모가 부족할 수 있으므로 결과를 NA와 지원 범위로 보고한다. 통제본을 정답 정제본이나 독립 검증셋으로 부르지 않는다. 반복·창 공유·긴 동일 궤적의 영향은 원본 위치로 감사한다.

### 8. H1 가압력 지배 민감도

Raw4 GMM을 주 분석으로 유지한다. 선택된 K·scaler 종류·covariance_type·regularization·seed를 고정하고 **F를 제외한 I/V/t**로 같은 날짜 분할 및 LODO fit을 한 번 더 수행한다. 날짜별 A/B component 조성의 분리 방향과 안정성을 Raw4와 비교하고, 정확 반복의 영향도 함께 표시한다. 입력 차원이 달라 Raw4와 I/V/t의 로그밀도 절댓값을 직접 우열 비교하지 않는다. I/V/t에서 구분이 약해지면 높은 F run 지배 가능성을 기록하되 물리적 두 트랙을 부정·확정하지 않는다. 고정 설정이 세 변수에서 수치적으로 실패하면 K를 다시 고르지 않고 실패와 이유를 기록한다.

## 성공/판단 기준

- **다중 regime 후보:** K1과 비교해 복수 component의 validation 밀도 개선이 fold·seed에 걸쳐 관찰되고, A/B 날짜의 component 조성 차이가 원본 행뿐 아니라 반복·I/V/t 민감도에서도 해석 가능해야 한다. 반례 날짜·분모·모델 불안정을 함께 제시한다. K 선택이 흔들리면 안정된 상태 수는 보류한다.
- **이상 분포 후보:** 전역 희소성과 component 내부 이탈이 실제로 다른 원본 사례·날짜 분포를 드러내는지 확인한다. 높은 점수가 동일 가압 run·정확 반복·scale 선택에만 의존하면 그 의존성을 결론으로 기록한다.
- **잔차 방향 후보:** K_error·seed·fold를 바꾸어도 중립적인 pattern profile이 재등장하고 후보 수·날짜 지원이 충분한 경우에만 후속 조사 대상으로 남긴다. K_error=3을 세 불량 유형으로 명명하지 않는다.
- **Result 관련 결론:** 관측된 7~8일의 일별 탐색 관계만 보고한다. 미기록 0 가정·날짜 하나 제외·반복 통제에서 방향이 바뀌면 조건 의존으로 표시한다. 어느 결과도 행별 불량 라벨이나 인과 효과가 아니다.
- 실행 실패·지원 부족·단일 분포가 더 적절함도 유효한 실험 결과다. “성공”을 Result 건수에 맞는 anomaly 행 수로 정의하지 않는다.

## 데이터 누수 점검

- A/B 배치와 K_error=3은 이미 본 자료·Result 유형 수에서 나온 사전 탐색 가설이다. 이 9날짜에서 확인한 결과를 독립 발견으로 부르지 않는다.
- 5개 fold의 scaler·GMM·잔차 GMM·후보 풀 문턱은 각 train에서만 fit한다. validation은 전역 설정 선택, test는 선택 뒤 진단에만 사용한다. LODO에서는 고정된 설정으로 나머지 8일에 fit하고 해당 1일에 score만 적용한다. Result는 모든 학습·K 선택·feature 생성에서 제외한다.
- 5개 fold의 날짜 재사용과 장기 정확 반복 때문에 날짜 보류만으로 독립성이 성립하지 않는다. LODO에서 해당 날짜를 fit에서 빼더라도 전역 하이퍼파라미터 선택에는 9일 자료가 간접 사용되므로 완전한 외부 검증이라고 부르지 않는다. 동일 네 값/긴 일치 블록의 train↔validation/test 교차를 폭1 및 필요한 창 길이로 감사한다.
- 공정 상태나 점수를 Result 유형에 맞춰 재명명·재선택하지 않는다. test 결과를 본 뒤 K·feature·split을 바꾸면 그 변경은 별도 후속 계획으로 분리한다.
- 겹친 행·창과 같은 날짜의 다수 기록을 독립 품질 관측으로 세지 않는다. 평가 단위가 행/날짜/반복 블록 중 무엇인지 모든 표에 명시한다.

## 사후 요청 후속 검증 — 물리 proxy와 행·사이클 후보 (2026-09-27)

이 절은 원래 GMM 설정 선택과 결과 확인 **이후** 요청된 탐색이다. 사전 등록된 YSH-007 본 가설의 독립 확인으로 취급하지 않는다. 기존 Raw4 GMM·9회 LODO 모델과 점수는 고정하며 재학습하지 않는다.
