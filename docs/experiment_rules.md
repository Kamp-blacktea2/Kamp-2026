# 실험 규칙

목적: 개인의 탐색을 보존하면서 팀이 질문, 결과, 다음 행동을 비교할 수 있게 합니다.

1. 모든 실험은 `experiments/<NBJ|YSJ|YSH>/` 아래에서 수행합니다.
2. 개인별로 `EXP001_짧은이름`, `EXP002_짧은이름` 순으로 번호를 부여합니다. 공유 참조는 `NBJ/EXP001_짧은이름`처럼 담당자를 포함합니다. 기존 번호는 재사용하지 않습니다.
3. 시작 전에 공용 템플릿으로 `실험계획.md`를 작성하고, 가능하면 하나의 질문/가설을 검증합니다.
4. EDA, PREPROCESSING, FEATURE, ML, DL, VALIDATION, ERROR_ANALYSIS 등은 `실험계획.md`의 실험 유형과 개인 `실험기록.md`의 유형 열에 metadata로 기록합니다. 유형별 상위 폴더는 만들지 않습니다.
5. 종료 후 `실험결과.md`를 작성합니다. 실패·중단한 실험도 삭제하지 말고 오류와 원인, 재시도 조건을 남깁니다.
6. 개인 `실험기록.md`의 상단 현재 정보와 표를 갱신하고, 각 실험에 질문/변경/결과/다음 행동을 3~4줄로 요약합니다. 필요하면 상세 계획·결과 문서로 연결합니다.
7. 실행 명령, 환경, 코드 버전, 데이터 버전/위치, 설정, 재현 여부를 기록합니다. 원본 데이터·비밀값·대용량 산출물은 commit하지 않습니다.
8. 공용화할 코드는 실험에서 검증한 뒤 호출부와 영향 범위를 확인하고 PR 리뷰를 통해 `src/`로 승격합니다.

상태 표기: 계획 / 진행 중 / 완료 / 실패 / 중단. 결과의 채택 / 보류 / 폐기는 상태와 별도로 기록합니다. 폐기는 접근법을 채택하지 않는다는 뜻이며 기록 삭제를 뜻하지 않습니다.
